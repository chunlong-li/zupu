# Windows 客户端 · 改动说明

## 版本号规则（必须遵守）

> 本条为用户明确约定，2026-11-12 起生效。**只改 `ZupuClient.csproj` 里的三处，不要动别的。**

| 场景 | 规则 | 例子 |
|---|---|---|
| 三段基础号 `n.n.n` | **固定不动**。第一、二段只有用户明确说明时才改 | `1.2.0` |
| 发**正式版** | 第三段 **+1** | `1.2.0 → 1.2.1` |
| 加功能 / 修 bug | 发**测试版**：`<当前正式版三段>.<MMDD>.<当天第几次>` | `1.2.0.1112.1`、`1.2.0.1112.2` |

实现方式（5 段号不是合法程序集版本）：

```xml
<Version>1.2.0</Version>                                  <!-- 三段，AssemblyVersion 用它 -->
<InformationalVersion>1.2.0.1112.1</InformationalVersion>  <!-- 完整号，界面/更新比较用它 -->
<IncludeSourceRevisionInInformationalVersion>false</IncludeSourceRevisionInInformationalVersion>
```

界面显示、`--version`、更新比较、更新包清单里的 `version` **一律用完整号**（`ClientUpdater.CurrentVersion`）；
需要三段时用 `ClientUpdater.BaseVersion`。

## v1.2.0.1113.6（本次）：登录页加「设置」入口，MSI 中文化 + 修协议乱码

### 在线安装包：改用系统自带 .NET Framework（68.5 MB → 52.5 KB）

界面不变（安装位置 + 浏览… + 三个勾选项 + 安装/取消 + 进度条），但**不再打包 .NET 8 运行时**：

- 源码：`ZupuSetupFx\Program.cs`，用系统自带的 `csc.exe`
  （`%SystemRoot%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`）编译，不需要 SDK；
- 依赖：Windows 自带的 **.NET Framework 4.8**（Win10 1903+ / Win11 默认都有）；
- 体积：**52.5 KB**（原来 68.5 MB）；
- 编译命令见 `ZupuSetupFx\build.cmd`。

两个 .NET Framework 特有的坑：

1. **默认走 TLS 1.0**，连更新源会报「未能创建 SSL/TLS 安全通道」——
   必须在启动时 `ServicePointManager.SecurityProtocol = Tls12 | Tls11`；
2. 自带 `csc` 只支持 **C# 5**：不能用 `out var`、字符串插值、表达式体成员。

装完自动关窗；失败弹窗显示原因，并把完整异常写到安装包同目录的 `install-error.log`。

#### 卸载（修过一个 bug）

之前 `UninstallString` 写的是**客户端本体**，所以控制面板点「卸载」等于打开客户端。
现在：

- 安装时把安装包自己复制一份到 `<安装目录>\uninst.exe`；
- 注册表写 `UninstallString = "<安装目录>\uninst.exe" --uninstall`
  （另有 `QuietUninstallString` 带 `--quiet`，给批量卸载用）；
- `uninst.exe --uninstall` 会：确认 → 关掉客户端 → 删桌面/开始菜单快捷方式 →
  删开机自启和卸载注册项 → 等自己退出后用 `rmdir` 删程序目录；
- **数据目录（`%LOCALAPPDATA%\ZupuClient`）保留**，弹窗里会写明。

#### 排查中踩到的坑（重要）

之前多次出现「没有可写的安装目录」：`%LOCALAPPDATA%`、`%APPDATA%`、`%USERPROFILE%`、
`C:\Users\Public`、`%ProgramData` 全部 `ERROR_ACCESS_DENIED (0x80070005)`，只有安装包所在目录能写。

原因是：**安装包放在了 DSH 工作区里（`D:\DeepSeek Harness\...`）再运行**——DSH 对子进程有
workspace-write 限制，工作区外一律不可写。把同一个安装包复制到 `C:\Users\Public` 再双击，
立刻正常装进 `%LOCALAPPDATA%\Programs\族谱客户端`（实测 232 个文件 + 桌面快捷方式）。

所以：**安装包从「下载」目录双击即可，不要从工作区目录里运行**。安装器自身也保留了兜底
（用户目录 → 公共目录 → 安装包所在目录），并会在界面上提示改装到了哪里。

### 在线安装包改为「下载 MSI → 交给 msiexec」

排查中发现：在某些机器上，这个 exe 被进程级策略限制成**只能写自己所在目录**——
自检日志显示 `%LOCALAPPDATA%`、`%APPDATA%`、`%USERPROFILE%`、`C:\Users\Public`、`C:\ProgramData`
全部 `ERROR_ACCESS_DENIED (0x80070005)`，只有 exe 同目录能写；而同机普通权限的 PowerShell 写这些位置正常。
所以「自己解压安装」这条路在那种环境下不可能成功。

现在在线安装包的流程是：

1. 读 `Client/latest.json` 拿到版本；
2. 下载 `Client/1.2/族谱客户端v<版本>.msi`（优先下到 exe 同目录——那儿一定可写）；
3. `msiexec /i <msi>` 把安装交给 Windows Installer（它以自己的身份写盘，不受这个限制）；
4. 向导关闭后自动删掉下载的 MSI。

只想要旧的解压安装行为时设 `ZUPU_INSTALL_MODE=unpack`。
下载位置仍按 `%TEMP%` → 安装目录 → 上级依次探测，出错会列出每个路径的具体错误。

**另一个真实故障（截图反馈）**：安装时往下下载文件放到了「安装目录的上一级」——
也就是 `%LOCALAPPDATA%\Programs\`，有些机器上这层写不进去，于是 3% 就报
`Access to the path '...\Programs\.zupu-install-xxxx.zip' is denied`。现在的处理：

- 下载位置按 `%TEMP%` → 安装目录 → 安装目录上一级 依次探测，取第一个真能写的；
- **下载前先检查安装目录可写**，不可写就按 `%LOCALAPPDATA%\族谱客户端` →
  `%APPDATA%\族谱客户端` → `%USERPROFILE%\族谱客户端` 自动换，并提示换到了哪里；
- 都不可写才报错，错误里列出试过的每个路径，并提示用 `--dir` 指定。

- 子系统从 `Exe` 改成 `WinExe`，不再有控制台窗口；
- 静默模式（`--quiet`）用 `AttachConsole` 接到调用方控制台，运维脚本仍能读输出；
- 窗口是**无边框自绘标题栏**（自己画 ✕ 和拖动），绕开了这台机器上系统标题栏中文乱码的问题；
- 窗口创建失败会写 `%LOCALAPPDATA%\ZupuClient\install-ui.log` 并退回无界面安装，不会卡死。

### 登录页可以进设置了

登录前看不到设置，导致「没装服务端的人根本进不去」——现在登录窗底部有：

```
⚙ 设置（安装服务端 / 客户端更新）
```

点开就是完整设置窗（数据目录 / 客户端更新 / 服务端 / 开机自启 / 关闭行为 / 缓存 / 关于），
可以在这里直接**安装本地服务端**、改更新源、设开机自启；关掉设置后如果服务器地址为空，会自动回填。

顺带修了登录窗的两个布局问题：标题被 8px 的绝对行高压扁、窗口高度不够导致底部控件被裁。

### MSI 安装界面

- 编译加 `-culture zh-CN`，欢迎页/按钮全部中文（「欢迎使用 族谱客户端 安装向导」「上一步/下一步/取消」）；
- **协议乱码**：原来是手写 RTF（`\uNNNN?` 转义在大于 32767 的码点会溢出），
  改成用 RichEdit 控件生成标准 RTF（`\ansicpg936` + GBK 字节），系统自带的 RichEdit 直接正常显示。

### 已验证

- 登录页点「⚙ 设置」→ 弹出 880×620 设置窗，左侧「服务端」可进；
- MSI 欢迎页截图确认全中文（见 `docs/msi-welcome-preview.png`）；
- 协议文件头：`{\rtf1\ansi\ansicpg936\deff0...{\fcharset134 Microsoft YaHei UI;}`，含 GBK 中文字节。

## v1.2.0.1113.4：开机启动时等本地服务端就绪

### 为什么

开机后客户端和服务端同时被拉起，客户端往往先起来，此时服务端还在初始化，
于是登录/首页直接连不上，得自己点刷新。现在客户端会等一等。

### 规则

只在**开机自启拉起**时生效（自启项命令行带 `--autostart-launch`），手动双击不受影响；
并且必须满足「服务端开机自启是开着的」+「连的是本机地址」：

```
连的是远程服务器（nas/域名） → 不等待（没有本地服务端可等）
本地服务端已在响应           → 不等待
本地服务端还没起来           → 显示等待窗，探测到响应立刻放行
```

等待窗：`正在等待本地服务端启动…` + 进度条 + `已等待 N 秒` + `跳过等待`。

- 每 0.7 秒探测一次，**任何 HTTP 响应**都算就绪（401/403 也说明服务活着）；
- 等满 6 秒还没起来、且服务端进程不在 → 客户端主动拉一次 `start.bat`；
- 90 秒仍无响应 → 提示"服务端还没起来，先打开客户端"，照常进界面，不卡死。

### 顺带

- 启动时会把 `HKCU\...\Run` 里 `ZupuClient` 的值**刷新成当前命令行**：
  程序目录被挪过、或者是老版本没带 `--autostart-launch`，都会自动纠正。

### 已验证

mock 一个服务端（18080，先不监听）：

```
13 秒截图：等待窗 420×176，「已等待 10 秒」，进度条约 11%
日志      ：boot wait: 等待服务端 http://127.0.0.1:18080/
随后启动 mock 服务端
日志      ：boot wait: 结束，就绪=True   → step 3: session=True
窗口      ：等待窗消失，主窗口 900×700 出现
```

## v1.2.0.1113.2：修「开机自启无效」

### 现象

设置里打开「客户端开机自启」，注册表也写了，但开机后客户端不出现。
（这台机器上实测：开机后 `startup.log` 里完全没有那次启动的记录。）

### 根因

Windows 从 `HKCU\...\Run` 拉起程序时，**当前工作目录是 `C:\Windows\System32`**。
Chromium 初始化时要在 profile 目录建锁文件、写运行期文件，在这个目录下被拒绝
（`Lock file can not be created: 拒绝访问 (0x5)`），libcef 里直接断言崩溃：

```
出错模块：libcef.dll      异常代码：0x80000003
```

进程一起来就死，所以看起来就是"没自启"。

对照实验（同一个 exe，只改工作目录）：

| 工作目录 | 结果 |
|---|---|
| `C:\Windows\System32` | 秒退，事件日志 APPCRASH / libcef 0x80000003 |
| 程序目录 | 正常，`step 2 OK`、进入主界面 |

### 修复

1. `Program.Main` 第一件事 `Directory.SetCurrentDirectory(AppContext.BaseDirectory)`，
   把工作目录钉回程序目录，CEF 再怎么用相对路径都落在可写的地方。
2. 启动日志里带上 `cwd=`，以后再出这类问题一眼能看出来。

### 顺带加固

- **任务管理器禁用检测**：Windows 把启动项禁用后写的是
  `...\Explorer\StartupApproved\Run` 的二进制标志位（注册表值还在，系统却会跳过）。
  现在设置页会显示「已登记，但被『任务管理器 → 启动』禁用」；重新打开开关时会顺手清掉该标志。
- 启动文件夹兜底脚本改成 **UTF-8 + `chcp 65001`**，中文路径不再乱码。

### 已验证

用计划任务以 `cwd=C:\Windows\System32` 启动新版（等同 Run 项的启动条件）：
进程存活、窗口正常出现；同一条件下修复前必崩。

## v1.2.0.1113.1：在线更新改用独立更新器

### 问题

上一版客户端自更新是「写一个 `apply-update.cmd`，用 `robocopy` 覆盖」，
两个硬伤：

1. 批处理文件的编码和 `cmd` 的代码页不一致，**路径里一旦有中文就乱码**，替换直接失败；
2. 解压暂存在 `数据目录\update\stage-*` 就没人清理，看着像"解压到另一个文件夹"。

### 现在的做法（照着 DSH 自己的更新器模式）

新增独立程序 **`ZupuUpdater.exe`**（单文件自包含，11.6 MB，随安装包一起分发）：

```
客户端：下载 → 校验 SHA256 → 解压到 stage → 启动 ZupuUpdater → 自己退出
更新器：等客户端真退出 → 按 Unicode 路径覆盖程序目录 → 启动新版 → 清理 stage 与下载包
```

关键点：

| 关注点 | 处理 |
|---|---|
| 中文 / 空格路径 | 全程 .NET 文件 API（Unicode 原生），**不经过 cmd**，不会乱码 |
| 传参 | `ProcessStartInfo.ArgumentList` 逐项传，自动转义 |
| 数据安全 | 只覆盖包内文件，**不删除**程序目录里多出来的（`settings.json`、`cef-cache`、日志） |
| 写入失败 | 每个文件 8 次退避重试（等旧进程释放句柄） |
| 更新器升级 | 更新包自带 `ZupuUpdater.exe`，客户端优先用**包内那份**，所以更新器能随包升级 |
| 清理 | 更新成功后删 stage 与下载的 zip；客户端启动时再兜底清一次遗留 stage |
| 兜底 | 万一包里没有更新器，才退回原来的批处理（并补 `chcp 65001` + UTF-8 BOM 写文件） |

### 顺带

- 服务端全量包的下载文件名改成 **ASCII**（`server-<版本>.tar.gz`），不再拿源站的中文包名当本地文件名。
- 更新器日志写到 `数据目录\update\updater.log`，失败可直接看。

### 已验证

用**带空格和中文**的真实路径做替换测试：

```
stage = D:\…\测试 目录\暂存      app = D:\…\测试 目录\程序
→ 退出码 0
→ settings.json 保留 ✓   新增文件.txt 到位 ✓   子目录 中文\深层.txt 到位 ✓
→ 暂存目录已删 ✓   下载包已删 ✓
→ 日志：已更新 2 个文件 / 启动新版客户端 / 已清理暂存目录 / ==== 更新完成 ====
```

日志里的中文路径原样保留，无乱码。

> 注意：本次是**从旧版（用批处理）升上来的最后一次**，如果旧客户端装在含中文的路径下，
> 这一跳可能仍旧走老逻辑；建议直接用安装包装一次 1.2.0.1113.1，之后所有更新都走新更新器。

## v1.1.3：侧栏图标看不清 → 改为位图渲染

### 问题

侧栏菜单的 emoji 图标**几乎看不见**。放大 3 倍才看清：GDI+ 把 emoji 画成了极细的单色轮廓线，
在 `#3a3226` 深色底上等于没有图标。

### 原因

GDI+（`Graphics.DrawString`）不支持 COLR/CPAL 彩色字体，只能按当前画笔色画单色轮廓；
Segoe UI Emoji 的轮廓笔画很细，小字号下就糊成一片。

### 处理

1. 新增 `EmojiImage.cs`：用 WPF（`FormattedText` + `RenderTargetBitmap`）把 emoji 预渲染成位图并缓存，
   GDI+ 直接 `DrawImage`。图标从"细线轮廓"变成实心字形，清晰可见。
   - `csproj` 加 `<UseWPF>true</UseWPF>`（仅用于这段渲染），并显式补回被 WPF SDK 改掉的隐式 `using`。
   - 渲染失败时自动退回原来的单色 emoji 文字，不会白屏。
2. 图标尺寸：一级菜单 `18px`、二级 `16px`，与文字基线居中。
3. 顺带修掉标题字体回退：这台机器**没装 SimSun**，`Theme.LogoFont()` 改为
   `SimSun → NSimSun → 宋体 → STSong → FangSong → KaiTi → Microsoft YaHei UI` 依次尝试。

### 已知限制（重要）

**图标仍是白色单色，不是网页那种彩色 emoji。** WPF 的文本栈同样不支持彩色字体（COLR/CPAL），
实测渲染出的像素全是灰阶。要在原生控件里得到真彩色 emoji，需要直接走 DirectWrite 的
`IDWriteFactory2/3` 彩色字形接口（COM 互操作量大），或者改为手绘一套彩色矢量图标。

如果必须要和网页一模一样的彩色 emoji，请确认走哪条路：
- 手绘彩色矢量图标（约 25 个图形，工作量中等，效果可控）
- 保持现在的白色单色图标（清晰、与深色侧栏协调）

## v1.1.2：修复侧栏分组内的菜单项点了没反应

### 问题

v1.1.1 里，**分组（数据看板 / 世系可视化 / 谱头文化 / 祠墓 / 系统设置）下面的 30 个菜单项全部没有响应**，
只有 10 个顶层项（成员管理、房支管理、…）能点。表现就是"侧栏大部分点了无效"。

### 原因

`MainForm.BuildMenuRows()` 建子项时只把行加进了容器和路由表，**忘了给子行订阅 `Activated` 事件**
（顶层项订阅了，子项漏了）：

```csharp
foreach (var child in node.Children!)
{
    var cr = new MenuRow { ... };
    _menuHost.Controls.Add(cr);
    _rowsByRoute[child.Route] = cr;
    kids.Add(cr);
    // ← 这里缺 cr.Activated += ...
}
```

`MenuRow.OnClick` 里 `Activated?.Invoke(...)`，没有订阅者 → 点击什么都不发生。

### 修复

1. 子项补上事件订阅，和顶层项走同一条 `Navigate(label, route)`。
2. `Navigate` 增加**结果校验 + 二级兜底**，避免以后再出现"点了没反应"：
   - ① 点网页里文本相同的 `li.el-menu-item`（走 vue-router，不刷新）
   - ② 直接调网页的 `__vue_app__.config.globalProperties.$router.push(route)`
   - ③ 整页跳转 `LoadUrl(地址 + 路由)`
   每一步之后都轮询 `location.pathname` 确认真的跳过去了，没跳才走下一步；仍在原页时直接返回。
3. 注入 CSS 的日志降噪：只有"重试过"或"最终失败"才写日志。

### 验证方式

用真实鼠标点击（`SetCursorPos` + `mouse_event`）点子项「🎂 生日」，服务端收到：

```
解码 = "nav=🎂 生日 @/birthday"
```

即：原生子项 → `Navigate` → 命中网页隐藏菜单项并点击 → 路由切到 `/birthday`。
同时 `shell.log` 记录 `navigate '🎂 生日' -> /birthday`。

## v1.1.0：改用 CefSharp，彻底摆脱对 WebView2 的依赖

### 为什么改

v1.0.0 用 `Microsoft.Web.WebView2` 嵌网页，依赖系统安装 **Edge WebView2 运行时**。
这台机器是精简版镜像，运行时缺失且商店/离线安装包都无法安装（`0x80070005`），

用户机器什么都不用装。

### 代码改动

| 文件 | 改动 |
|---|---|
| `ZupuClient.csproj` | 移除 `Microsoft.Web.WebView2`；加入 `CefSharp.WinForms.NETCore 156.0.150`；版本号 1.0.0 → **1.1.0** |
| `Program.cs` | 启动时 `Cef.Initialize()`、退出时 `Cef.Shutdown()`；初始化失败给出明确提示；新增启动日志与崩溃日志 |
| `MainForm.cs` | `WebView2` → `ChromiumWebBrowser`；`ExecuteScriptAsync` → `EvaluateScriptAsync`；`Source=new Uri()` → `LoadUrl()`；CEF 回调统一切回 UI 线程 |

| `AppPaths.cs` | **新增**：数据目录解析，支持环境变量 `ZUPU_DATA_DIR` 覆盖（绿色版/便携部署） |

### 顺手修掉的问题

1. **房支下拉误触发**：填充下拉时 `SelectedIndexChanged` 会以 -1 触发切换，每次进主界面多调一次
   `__zupuSetBranch(0)`。现在用 `_fillingBranches` 标志屏蔽。
2. **脚本注入更稳**：原 `Esc()` 逐字符替换容易漏，改为 `JsString()` 生成完整 JS 字符串字面量
   （含引号、反斜杠、`\r`、`U+2028`、`U+2029`）。
3. **空处理器清掉**：`WebMessageReceived += (_, _) => { }` 删除。
4. **加载失败可见**：新增 `LoadError` 处理，主框架加载失败时顶栏显示错误码，不再白屏无提示。

## v1.0.0：原始代码的修复与安全加固

针对最初 9 个文件的原代码（**无法编译**）的修复与加固。

### 一、修复的编译错误

| 文件 | 问题 | 处理 |
|---|---|---|
| `ZupuClient.csproj` | 引用 `app.ico`，但包内没有该文件 | **新生成** `app.ico`（7 个尺寸） |
| `MainForm.cs:20` | `if (...) A = x, B = y;` —— C# 不支持逗号连写语句 | 改为 `if { … } else { … }` |

### 二、安全加固

1. **密码 DPAPI 加密存储**：落盘字段 `PassEnc`（`DataProtectionScope.CurrentUser` + 应用专属熵），
   明文只在内存；旧版明文 `Pass` 字段自动迁移并清空；换用户/换机器解不开按"未保存"处理。
2. **TLS 证书校验**：原为 `(_, _, _, _) => true`（全放行）。现在公网一律严格校验；仅本机/私网
   （10/8、172.16/12、192.168/16、169.254/16、127/8、`localhost`、`.local`、IPv6 回环/fe80::/10/fc00::/7）
   允许自签，且采用**首次信任 + 指纹固定（TOFU）**，同主机证书变化即拒绝。
3. **脚本注入加固**：补齐 `\r`、`U+2028`、`U+2029`（v1.1.0 进一步改为 `JsString()`）。

### 三、健壮性

- WebView2/CEF 缺失时弹窗给出可操作提示，不再抛未捕获异常。
- 局域网扫描实时显示进度「已发现 N 个设备…」。

### 四、编译方式

本机使用便携版 .NET SDK 8.0.404（解压在 `D:\DeepSeek Harness\zupu\_dotnet\sdk`，未做系统安装）。
因当前环境写不了 `C:\Users\Administrator` 的部分路径，编译时需重定向这几个变量：

```powershell
$base = 'D:\DeepSeek Harness\zupu\_dotnet'
$env:DOTNET_CLI_HOME = "$base\home"
$env:NUGET_PACKAGES  = "$base\nuget\packages"
$env:APPDATA         = "$base\appdata"
$env:LOCALAPPDATA    = "$base\localappdata"
$env:TEMP = "$base\tmp"; $env:TMP = "$base\tmp"

& "$base\sdk\dotnet.exe" publish `
    D:\DeepSeek Harness\zupu\windows-client\windows-client\ZupuClient.csproj `
    -c Release -r win-x64 --self-contained true `
    -o D:\DeepSeek Harness\zupu\windows-client\publish-cef `
    -p:RestoreConfigFile="$base\nuget\NuGet.Config"
```
